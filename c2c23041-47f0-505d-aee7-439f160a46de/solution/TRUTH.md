## The single most important insight

You are asked to make one nginx server play two roles at once: the TLS terminator that verifies each client certificate against a root plus intermediate chain with a CRL, and its own forward-auth backend that gates every public request on the verified subject. The auth backend does not run in a separate process. It lives as an `internal` location inside the same nginx that just finished the handshake, and the only signal it consults is the `$ssl_client_s_dn` variable that `ngx_http_ssl_module` populates when the client leaf certificate is verified. Every design that reaches for an external Flask or Go auth service throws away the TLS context, because HTTP hops downstream of the handshake do not carry `$ssl_client_s_dn` and the shipped upstream on `127.0.0.1:8080` is a plain echo, not an authorization service.

The second half of the insight is that revocation, chain depth, and the peer-identity guard live in three different nginx layers and each one is load bearing for a specific probe. The CRL runs during the TLS handshake, before any HTTP request exists, so a missing `ssl_crl` lets the revoked `svc-delta` client through and fails P5. The chain depth of 2 is required because `client-ca.crt` bundles a root plus an intermediate and every shipped client is signed by the intermediate, so depth 1 breaks even the valid `svc-alpha` client and fails P1. The `CN=svc-*,O=Ethara` DN guard runs inside the `auth_request` subrequest after the handshake and rejects any authenticated client whose subject does not match the Ethara service namespace. Any one of the three missing is a probe failure that cannot be masked by tightening the other two.

## The ideal solve, step by step

1. **Bind the :443 listener to the pinned server material and lock the negotiator to TLSv1.3.** Inside `server { listen 443 ssl http2; server_name localhost; }` set `ssl_certificate /workspace/input/pki/server.crt;`, `ssl_certificate_key /workspace/input/pki/server.key;`, and `ssl_protocols TLSv1.3;`. Probe P7 sends `curl --tlsv1.2 --tls-max 1.2` and expects a nonzero curl exit; if you leave TLSv1.2 enabled the negotiator succeeds and P7 fails. Why it matters: the pinned material is the only server keypair the verifier trusts (via `--cacert server-ca.crt`), so pointing at any other certificate makes every probe fail at the trust check before the other layers even run.

2. **Turn on client-certificate verification against the two-cert bundle and walk the chain at depth 2.** Add `ssl_verify_client on;`, `ssl_client_certificate /workspace/input/pki/client-ca.crt;`, and `ssl_verify_depth 2;`. The `client-ca.crt` file is a concatenated root plus intermediate PEM. Depth 1 lets nginx follow one signature hop and stops at the intermediate before reaching the leaf, so every valid client fails handshake with `unable to get local issuer certificate`. Depth 2 walks leaf then intermediate then root and terminates on the trust anchor. Probe P4 sends a client signed by an unrelated root and fails at handshake because that root is not in the bundle regardless of depth.

3. **Wire the CRL into the same server block so revocation runs at the handshake layer.** Add `ssl_crl /workspace/input/pki/client-crl.pem;`. Nginx consults the CRL as part of X.509 validation, before any HTTP request is dispatched, which is exactly why probe P5 (revoked `svc-delta`) has to fail with 495 rather than 401 or 403: no HTTP request ever reaches your `/_verify` location. A DN-based denylist inside `/_verify` cannot cover this case because by the time the subrequest would run the handshake has already succeeded and the primary response would be 200.

4. **Declare the forward-auth backend as an `internal` location that consults `$ssl_client_s_dn`.** Add a block equivalent to `location = /_verify { internal; if ($ssl_client_s_dn !~ "CN=svc-[a-z0-9]+,O=Ethara") { return 401; } return 204; }`. The `internal` keyword makes the location unreachable from any external client, so a direct `GET /_verify` returns 404 rather than 204 or 401. This is exactly what probe P2 asserts. The regex `CN=svc-[a-z0-9]+,O=Ethara` is the Ethara service-account namespace; it accepts `svc-alpha` but would reject `CN=root,O=Ethara` or `CN=svc-alpha,O=Attacker`. The `if` block runs on each subrequest and is the DN-level authorization step.

5. **Chain the verifier into every public request via `auth_request`.** Inside `location / { ... }` (and any other publicly reachable location such as `/_echo_headers`) place `auth_request /_verify;` before the `proxy_pass` line. Nginx (via `ngx_http_auth_request_module`) issues an internal subrequest against `/_verify` before proxying; a 204 lets the main request proceed to the upstream and a 401 short-circuits the main request with the same status. Because the subrequest is served inside the same nginx worker, the SSL variables are still in scope. An external forward-auth service would instead need the subject reserialized into a header such as `X-Forwarded-Client-Cert`, which this task specifically avoids.

6. **Inject the verified subject into the upstream request and proxy to the stub.** In the public locations set `proxy_set_header Host $host;` and `proxy_set_header X-Verified-Subject $ssl_client_s_dn;`, then `proxy_pass http://127.0.0.1:8080/;`. Probe P1 exercises `/_echo_headers` through the same auth-guarded path and expects the echoed header block to contain `X-Verified-Subject: CN=svc-alpha,O=Ethara`; if you forget the injection the header never reaches the upstream stub, and if you forget the `$ssl_client_s_dn` reference the header arrives empty.

7. **Emit the JSON access log with the exact twelve-key vocabulary.** Define `log_format json_combined escape=json` with a single-line JSON object containing `request_id`, `remote_addr`, `ts_iso8601`, `request_method`, `request_uri`, `http_host`, `status`, `body_bytes_sent`, `request_time_seconds`, `ssl_client_verify`, `ssl_client_s_dn`, and `http_user_agent`, then set `access_log /var/log/nginx/access.log json_combined;`. The verifier parses every emitted line as JSON and asserts the key set is exactly those twelve names. Extra keys such as `ssl_protocol`, missing keys such as `http_user_agent`, or misspelled keys such as `ts` all fail the log check. Use `$time_iso8601` for `ts_iso8601` and `$request_time` for `request_time_seconds`; the `escape=json` flag protects against unescaped quotes in a User-Agent string that would otherwise corrupt the record.

8. **Add the plain-HTTP redirect server on :80.** Add `server { listen 80; server_name _; return 301 https://$host$request_uri; }`. Probe P8 hits `http://localhost/foo` and expects status 301 with Location `https://localhost/foo`. Writing `return 301 https://localhost/...` hardcodes the response host and breaks the redirect for every other value of Host; `return 302` loses the permanent-redirect grade. Preserve both `$host` and `$request_uri`.

9. **Author `/workspace/mime.types` with the minimum types the include needs.** Write a `types { text/html html htm; text/plain txt; application/json json; application/octet-stream bin; }` block. The `default_type application/octet-stream;` line in `nginx.conf` still applies, but the top-level `include /etc/nginx/mime.types;` must resolve for `nginx -t` to pass.

10. **Assemble `/workspace/reload.sh` as install then validate then start then wait.** Copy `/workspace/nginx.conf` to `/etc/nginx/nginx.conf` and `/workspace/mime.types` to `/etc/nginx/mime.types`; invoke `nginx -t -c /etc/nginx/nginx.conf` and abort with a nonzero exit on failure; quit any pre-existing nginx via `nginx -s quit` and wait for the process to exit; launch `nginx`; then poll `ss -ltn "sport = :443"` in a bounded loop for up to 5 seconds until `:443` is bound before `exit 0`. Finish with `chmod +x /workspace/reload.sh` so the D1 shape check sees the owner-executable bit set.

## Traps that catch agents that are not thinking carefully

- **Trap: Reaching for a separate forward-auth service.** The reflex is to run a small Flask or Go server on some port, point `auth_request` at it, and forward the client cert with `X-Forwarded-Client-Cert`. This loses `$ssl_client_s_dn` because that variable is only populated in the nginx worker that finished the TLS handshake, and the shipped upstream on `127.0.0.1:8080` is a plain HTML and echo stub with no authorization logic. Keep the verifier inside nginx as an `internal` location.

- **Trap: `ssl_verify_depth 1` for a root plus intermediate bundle.** Depth 1 accepts only clients signed directly by the trust anchor, so every shipped valid client (leaf signed by the intermediate) fails P1 with 495 even though the material is otherwise fine. Depth 2 is the minimum that lets the chain traverse leaf then intermediate then root.

- **Trap: Skipping `ssl_crl` because `svc-delta` looks valid on its face.** Without the CRL directive nginx accepts `svc-delta` as a well-formed leaf against the trusted chain, and P5 returns 200 instead of 495. An HTTP-layer denylist inside `/_verify` cannot cover it because the handshake has already succeeded and the primary response is 200 for a compliant DN.

- **Trap: `ssl_verify_client optional` or `optional_no_ca`.** The grader's shortcut pattern set includes `ssl_verify_client\s+(off|optional_no_ca)` as a hard-fail regex, and `optional` alone bypasses mTLS because the request proceeds even when the client sent no certificate. Use `on` verbatim; the corresponding no-cert probe P6 returns 496 via the built-in error path.

- **Trap: Forgetting that `/_verify` must be `internal`.** If the location is reachable from the outside, probe P2 (a direct GET on `/_verify` from a valid client) returns 204 instead of 404, and the exposed endpoint becomes a probe oracle for the DN regex. Adding `internal;` is a one-line fix.

- **Trap: JSON log field drift.** Adding a convenient extra field like `ssl_protocol`, dropping `http_user_agent`, or renaming `ts_iso8601` to `ts` fails the access-log check on the first line the probe matrix generates. The bound set is exactly the twelve keys with the exact case and spelling the instruction lists, and `escape=json` is not optional because probes routinely carry quotes in `User-Agent`.

- **Trap: Hardcoded `Location: https://localhost/foo` in the :80 block.** A literal `return 301 https://localhost/...` collapses every requesting host into `localhost` and breaks the redirect semantics. `return 301 https://$host$request_uri;` preserves both, which is what probe P8's Location assertion demands.

- **Trap: `reload.sh` racing nginx into the background and exiting 0 while :443 is unbound.** The verifier re-runs `nginx -t -c /etc/nginx/nginx.conf` after your script exits and separately polls for `:443` for 5 seconds, so a script that fires `nginx &` and exits early trips D2 even when the config would eventually load. Poll `ss -ltn "sport = :443"` in a bounded loop and exit nonzero on timeout.

- **Trap: Skipping the `nginx -t` gate before `nginx` starts.** A syntactically broken config that nonetheless spawns worker processes leaves nginx half-alive and the verifier's follow-up `nginx -t` fails D2. Run `nginx -t -c /etc/nginx/nginx.conf` first and abort loudly on any nonzero exit before ever calling `nginx`.

- **Trap: Pasting anything from `solution/` or a canary token into the three files.** The bytes-level shortcut scan sweeps `nginx.conf`, `mime.types`, and `reload.sh` for regexes like `solution/grounding\.yaml`, `solution/TRUTH\.md`, and `FORGE_HOLDOUT_CANARY_[A-Z0-9]{32}`. A stray comment like `# per solution/grounding.yaml`, a paste from `dataset/<uuid>/tests/`, or an accidental canary literal zeros the score even if every probe passes.
